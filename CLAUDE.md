# 벌꿀이 (Beolkkuri)

Bee Swarm Simulator macro for macOS and Windows with a React + shadcn/ui interface. It started as a fork of Fuzzy Macro (itself built on Existance Macro), was fully rebranded, and was given a new UI for Korean users who don't code. Korean is the default UI language, with an English toggle. Talk to the owner (Yoon-robin) in Korean.

## Layout

```
src/              Python macro (macOS and Windows, see "Platforms"). main.py starts it; gui.py exposes functions to the UI via eel.
  modules/        macro logic, settings (misc/settingsManager.py), updater (misc/update.py), AI models (misc/modelManager.py)
  webapp/         BUILT UI — generated by `pnpm --dir ui build`, committed so users get it. Never edit by hand.
ui/               React 19 + Vite 6 + TypeScript + Tailwind v4 + shadcn/ui (radix, nova preset) source
  dev/            dev_server.py (HTTP backend for the browser), eel_harness.py (serves the build through real eel)
  scripts/        extract-schema.mjs (one-off migration, see "Settings schema")
paths/, settings/ movement paths and gather patterns used by the macro
install.sh        one-line installer: downloads latest release (or main) into ~/Beolkkuri, runs install_dependencies.command
install_dependencies.command / run_macro.command   macOS installer and launcher (bash, LF, must stay executable)
install.ps1       Windows one-liner (`irm … | iex`): downloads and opens the latest Beolkkuri-Setup.exe; falls back to the source install below
install_dependencies.bat / run_macro.bat   Windows source install: double-click wrappers for scripts/windows/*.ps1
scripts/windows/  install_dependencies.ps1 and run_macro.ps1 (source install and launcher), build_installer.ps1 + installer/ (Beolkkuri-Setup.exe, see "Windows installer")
requirements-windows.txt   Python packages for Windows (macOS pins its own in install_dependencies.command)
docs/             Korean help pages linked from the app and README
site/             landing page (GitHub Pages): one static index.html + assets/. Deployed by .github/workflows/pages.yml
scripts/site/     screenshot tooling for the landing page (puppeteer-core; own package.json, not part of the app)
```

## Developing (any OS)

Needs Node 20+, pnpm, Python 3.9+.

```bash
pnpm --dir ui install
python ui/dev/dev_server.py     # 127.0.0.1:8765, real settingsManager + stubs for macro calls
pnpm --dir ui dev               # http://localhost:5173 (proxies /__py to the dev server)
```

`.claude/launch.json` has both as `beolkkuri-backend` / `beolkkuri-ui` for the preview tools.

- **The dev server reads and writes the real `settings/profiles/default` files** (created from defaults on first run; gitignored). Restore anything you toggle while testing.
- Macro-only calls (start/stop/tools/updates/permissions) are stubbed in `STUBS` in `ui/dev/dev_server.py`. Add a stub when the UI calls a new `gui.py` function, matching the real return shape. `DEV_PERMISSIONS` fakes Screen Recording as off until its "켜기" button is pressed.
- Before committing UI changes: `npx tsc -b` in `ui/`, then `pnpm --dir ui build`, and commit `src/webapp` together with the source. The in-app updater ships whatever is in `src/webapp`.
- After a build, check that only `bridge.js` contains literal `eel.expose(` (eel scans web files for that text to learn JS function names).
- Hot reload sometimes logs "useTheme must be used inside ThemeProvider"; a full reload clears it.

## How the UI talks to Python

- JS → Python: `callPy(name, ...args)` in `ui/src/lib/py.ts` calls `eel.name(...)()` in the app, or POSTs to `/__py/name` in dev. Typed shortcuts live in `py`.
- Python → JS: `ui/public/bridge.js` is a plain, unbundled script that defines and `eel.expose`s global functions (`log`, `loadInputs`, `toggleStartStop`, `getElementProperty`, ...). They forward to React handlers registered with `usePythonEvent` (`ui/src/lib/bridge.ts`). Add new Python-callable functions there.
- The app window is Chrome `--incognito`, so localStorage does not survive restarts. Persistent UI prefs go into general settings (`ui_language`, `ui_theme`).

## Platforms (macOS and Windows)

The Python code branches on `sys.platform` (`"darwin"` / `"win32"`). When adding a Windows path, keep the macOS one as it was.

- **Roblox window:** `modules/misc/appManager.py` imports `appManagerMac.py` (AppKit, AppleScript, Accessibility) or `appManagerWindows.py` (ctypes user32/kernel32: process list, client rect, focus, close). Both export the same functions plus `FULLSCREEN_HOTKEY`.
- **Keys:** Roblox ignores pyautogui's Windows key events (virtual-key codes only). `modules/controls/winInput.py` swaps pyautogui's `_keyDown`/`_keyUp` for `SendInput` with scan codes. `keyboard.py` installs it at import, so spawned processes get it too.
- **OCR:** Apple Vision (`ocrmac`) on macOS. On Windows, `modules/screen/winOcr.py` uses the built-in Windows.Media.Ocr through `winocr`. It upscales 4x because the engine misses small text otherwise. It prefers en-US and falls back to the user's languages; Korean Windows often has only `ko`, which still reads digits and most English.
- **Image matching:** the compiled `bitmap_matcher` `.so` is macOS only. Elsewhere `bitmap_matcher/numpy_matcher.py` provides the same three functions in NumPy.
- **Screen:** Windows coordinates are physical pixels (pyautogui makes the process DPI aware), so `screenData` reports a `built-in` display with no Retina factor. `screenshot.pillowGrab` uses `ImageGrab` instead of Quartz.
- **macOS only, skipped on Windows:**
  - permissions: `getPermissionStatus` returns all `None`, and the UI hides the banner and the guide step;
  - the ColorSync colour-profile check;
  - the notch scaling check;
  - `caffeinate` (Windows uses `SetThreadExecutionState`).
- **App window:** `gui.launch` opens Chrome in app mode; on Windows it falls back to Edge (`mode="edge"`) when Chrome is missing.
- **UI:** `ui/src/lib/platform.ts` exports `isMac` / `isWindows`. Strings that differ per OS pick their text inside the string tables (`isMac ? … : …`), so ko/en keys stay the same.

Windows install scripts (the source install; most users get Beolkkuri-Setup.exe, next section):
- **`install.ps1`** must be UTF-8 **without** a BOM, because `irm | iex` fails on a leading BOM.
- **`scripts/windows/*.ps1`** need UTF-8 **with** a BOM. Windows PowerShell 5.1 reads BOM-less files as ANSI, which breaks the Korean text.
- **`.bat` files** are CRLF (`.gitattributes`). Keep the launcher on one line, because cmd re-reads a .bat while it runs and the updater may replace it.
- **Python and packages:**
  - Python 3.12 (64-bit), installed per user from python.org if missing.
  - venv `%USERPROFILE%\beolkkuri-env`; override with `BEOLKKURI_VENV`.
  - Packages come from `requirements-windows.txt`, which is also passed to pip as a constraints file to keep `numpy<2`.
  - Log: `%USERPROFILE%\Beolkkuri-install.log`.
- **Installer switches:** `-Quiet` never prompts (the updater uses it after an update), plus `-NoShortcut` and `-NoLaunch`.
- **`run_macro.ps1`:** sets `PYTHONUTF8=1`, because Korean Windows defaults to CP949. Before starting, it closes an older Beolkkuri window from the same venv. It also sets `BEOLKKURI_LAUNCHER=1` and starts `main.py` again when it exits with code 75 (see "Updates").
- **Testing on Windows:** point `BEOLKKURI_VENV` at a test venv and run `run_macro.bat`. Or run `python main.py` in `src/` with `PYTHONUTF8=1`. The PowerShell tool is non-interactive, so test the installer with `-Quiet -NoShortcut`.
- **English OCR:** the source installer offers to add it. For Setup.exe installs, the first step of the Windows guide does it: `getOcrStatus` / `installEnglishOcr` in `gui.py` run `Add-WindowsCapability` elevated (one UAC prompt) on a thread, and the UI polls (`ui/src/state/ocr.ts`).

### Windows installer (Beolkkuri-Setup.exe)

Written from scratch in C# (no NSIS/Inno), compiled with the `csc.exe` that ships with .NET Framework 4 (`C:\Windows\Microsoft.NET\Framework64\v4.0.30319`), so **C# 5 only** (no `$""`, `?.`, `nameof`, expression bodies).
- `scripts/windows/installer/Setup.cs` is the installer and uninstaller window; `Launcher.cs` becomes `Beolkkuri.exe`; `app.manifest` (asInvoker, DPI aware).
- `scripts/windows/build_installer.ps1 [-Ref HEAD] [-Test]`:
  1. `git archive` of the ref (commit first, or pass `git stash create` as `-Ref`);
  2. the python.org NuGet package (Python 3.12, cached in `build/cache`) as `runtime/`;
  3. pip installs `requirements-windows.txt` into it;
  4. compiles both exes;
  5. writes `dist/Beolkkuri-Setup.exe` = stub exe + zip + 8-byte zip length + `BKPAYLD1`.
  `-Test` silent-installs to `build/installer/test-install` and import-checks it. Run csc from PowerShell, not Git Bash (Korean paths break).
- Install: per user, no admin, default `%LOCALAPPDATA%\Programs\Beolkkuri`. Start menu (and optional Desktop) shortcut `벌꿀이.lnk` → `Beolkkuri.exe`, uninstall entry under `HKCU\…\Uninstall\Beolkkuri`, `uninstall.exe` is a copy of the stub. Upgrades keep `settings/profiles`, `settings/patterns` and `src/data/user`; a first install imports them from an old `%USERPROFILE%\Beolkkuri`. Log: `%TEMP%\Beolkkuri-Setup.log`.
- Switches: `/S` silent, `/D=<folder>`, `/NoDesktop`, `/uninstall`, `/RemoveSettings`, `/lang=ko|en`, `/shot=<dir>` (renders every page to PNG at 2x; `site/assets/setup-ko.webp` / `setup-en.webp` come from these).
- `Beolkkuri.exe` runs `runtime\python.exe src\main.py` with `PYTHONUTF8=1`, `PYTHONNOUSERSITE=1`, `BEOLKKURI_LAUNCHER=1`, and starts it again on exit code 75.
- `runtime/`, `Beolkkuri.exe` and `uninstall.exe` are in `.gitignore`, and the updater never touches gitignored or protected folders, so in-app updates leave them alone.
- Look: the website's honey poster style, drawn by hand in GDI+ (Black Han Sans embedded as `title.ttf`, Malgun Gothic text, Segoe UI for paths because Malgun Gothic draws `\` as `₩`). Korean or English follows the Windows UI language.
- CI: `.github/workflows/windows-installer.yml` builds and tests it on every published release and uploads `Beolkkuri-Setup.exe` to that release (or run it by hand with a tag).

## Settings schema

- `ui/src/schema/legacy-schema.json` (65 sections / 247 settings) describes every standard setting row: id, type, options, save target. It was extracted once from the old jQuery UI with `ui/scripts/extract-schema.mjs` and then **edited by hand** (rebrand wording). Edit the JSON directly; don't re-run the extractor.
- `saveTargetOf(def)` decides profile / general / field / custom saving. Dropdown values are saved lower-cased like the legacy UI; numeric text boxes save strings (0 when empty). **Never change setting ids or value formats**, because Python reads them.
- Korean text for the schema: `ui/src/i18n/settings-ko.json` (settings by id; sections and options by English label; id-less separators as `sep:<title>`).
- Pages render schema sections with `SchemaSections` and customise them with `overrides` (`ui/src/components/settings/schema-section.tsx`).

## UI conventions

- **Strings:** app-wide strings go in `ui/src/i18n/ui.ts`; page strings go in a local `PageStrings` table read with `useStrings`. Always keep ko and en in sync. Korean copy uses natural, friendly 해요체 and stays short.
- **Motion utilities** in `ui/src/index.css`:
  - Easing tokens `--ease-out-soft` (things arriving) and `--ease-glide` (things moving between two places), also usable as `ease-out-soft` / `ease-glide`.
  - `.bk-page` staggers a page's children automatically (rise + slight blur, under ~0.4s in total). Tab panels use the shorter `.bk-tab-in`.
  - `.bk-stagger`, `.bk-shimmer`, `.bk-pop`, `.bk-swap` (an icon/label replacing another in place) and `.bk-flash` are opt-in.
  - The selected tab (`components/ui/tabs.tsx`) and sidebar item (`NavGlider` in `app-sidebar.tsx`) have one sliding highlight (`.bk-glider`) instead of per-item backgrounds.
  - No looping attention effects (glows, pulsing buttons): the macro can run for hours. The small status dot is the one exception.
  - There is a global `prefers-reduced-motion` override.
  - Theme switching uses a view-transition circle (`ui/src/lib/theme.tsx`).
- **Search palette** (Ctrl/⌘+K, `components/command-palette.tsx`): it jumps with `goToTarget` (`lib/focus.ts`). Pages with sub-tabs call `useTabRequest(page, setTab)`, and rows call `useFocusTarget`. Sub-tab labels live in `ui.ts` as `subtab.<page>.<tab value>`; the page and the palette both read them, so a new sub-tab needs that key plus the same hooks. A custom row needs `useFocusTarget`.
- **Run state:** `state/run-state.tsx` handles polling, the session timer and the start/stop toasts.
- **Permissions:** `state/permissions.ts` polls `getPermissionStatus` in `gui.py`.
- **Components:** use the shadcn components in `ui/src/components/ui` and Tailwind. Don't add dependencies casually.

## Landing page (`site/`)

- Live at https://yoon-robin.github.io/Beolkkuri/. Every push to `main` that touches `site/**` redeploys it (Pages source: GitHub Actions).
- A single hand-written `site/index.html` (no build step, no framework): inline CSS/JS. Korean by default, with an EN toggle remembered in localStorage (`beolkkuri_site_lang`; the old `rm_site_lang` is still read). Korean text lives in the HTML (`data-i18n` / `data-i18n-html`); the English strings are in the `EN` object in the script, so keep the keys in sync.
- Look: a bright honey "game poster" style, chosen so it doesn't read like a generic AI landing page.
  - Black Han Sans (Google Fonts) for headlines, Pretendard (jsDelivr) for text.
  - Ink outlines and hard offset shadows instead of glows, gradients and glass.
  - Sections alternate honey / paper / ink backgrounds.
- Motion is all in the script and CSS of that file, and everything has a `prefers-reduced-motion` fallback:
  - The hero honeycomb fills cell by cell, and bees fly around it with SVG `animateMotion`.
  - The screenshot straightens as you scroll, and honey drips at the hero's bottom edge.
  - The two tapes speed up with scroll speed.
  - `#hour` is pinned and scrolls sideways on screens at least 900×640; smaller screens get a plain grid.
  - Gallery screenshots change with a circle wipe.
  - The final headline fills with ink as you scroll.
  - The copy buttons give off honey sparks.
- macOS and Windows: the install commands (hero and `#install`), steps and help link follow the visitor's OS (`navigator.platform`), and the `#install` tabs switch them. On macOS, the hero and `#install` show the curl command, and `#install` has a demo terminal playing `MAC_SCRIPT`, shortened from what `install_dependencies.command` prints; keep it in step with the installer. On Windows, both show a download button for `releases/latest/download/Beolkkuri-Setup.exe`, and `#install` has the installer screenshot `site/assets/setup-<lang>.webp` (made with Setup.exe `/shot`, see "Windows installer").
- Preview: `python -m http.server 8790 --directory site` (`beolkkuri-site` in `.claude/launch.json`).
- Check it: `cd scripts/site && npm install && node check-site.mjs out`. This screenshots each section at desktop (1440), mobile (390) and English, and prints horizontal overflow and JS errors. Both should be 0/none.
- Refresh the app screenshots:
  1. Run the dev UI plus backend.
  2. `node scripts/site/shoot-app.mjs <dir>` (fake running state and logs, 2x).
  3. `python scripts/site/to-webp.py <dir> site/assets`.
- `site/assets/og.png` (1200×630 share card) and the mascot `site/assets/bee.png` come from the brand pipeline (see Brand rules). Re-render the share card after refreshing `site/assets/home.webp`, since it shows that screenshot.
- Set `CHROME=/path/to/chrome` if the scripts can't find a browser. On Windows with the sandbox on, Chrome may fail to launch; headless-shell with `pipe: true` worked.
- Copy rules: no made-up stats or user counts. "Not affiliated with Onett/Roblox" stays in the FAQ and footer.

## Repo housekeeping

- `.gitattributes` forces LF, except CRLF for `*.bat`. Windows has `core.autocrlf=true`, so expect CRLF warnings; they are harmless.
- `*.command` files must keep mode 100755. When adding one from Windows: `git update-index --chmod=+x <file>`.
- Version: `ui/public/version.txt`, copied to `src/webapp/version.txt` by the build. `src/modules/misc/update.py` compares it with GitHub releases of `Yoon-robin/Beolkkuri` (tags like `v1.0.0`; the leading `v` is ignored). `install.sh` installs the latest release zipball, or `main` if there are no releases.
- **Releasing:** bump `ui/public/version.txt`, rebuild the UI, commit and push, then publish a GitHub release whose tag matches (`v1.0.1`). The windows-installer workflow attaches `Beolkkuri-Setup.exe` to it a few minutes later; the website's Windows button and `install.ps1` download that file from the latest release.
- **Updates:** `update.py` downloads the release zip, swaps the files (keeping gitignored and protected paths such as profiles, `runtime/` and the exes), and on Windows installs new requirements with the bundled Python (`runtime\python.exe`) or the venv. When the app opens, `update-panel.tsx` checks for a new release and, with `auto_update` on (default) and the macro stopped, installs it and calls `restart_app()`. That exits with code **75** when `BEOLKKURI_LAUNCHER` is set (`Beolkkuri.exe`, `run_macro.ps1` start it again), uses `os.execv` on macOS, and on older Windows launchers starts `run_macro.bat` itself. With `auto_update` off it offers the update instead. Git checkouts never auto-update.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
